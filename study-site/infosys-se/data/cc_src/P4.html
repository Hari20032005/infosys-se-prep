1. The idea

Adding 1 to a variable is so common that programmers wrote a short form for it. If i is 5, then i++ makes it 6. So does ++i. In both cases i ends one higher.

The difference is the value you get back at that moment. Think of "pre" as "before" and "post" as "after".

  • ++i (pre-increment): add 1 first, then hand back the new value.
  • i++ (post-increment): hand back the old value first, then add 1.

So if i is 5, then ++i gives 6 and i++ gives 5. After either one, i is 6.

Exam setters love this because it is easy to get wrong when you hurry. The good news is that it needs one rule and one habit. The rule is the pair above. The habit is to write down i after every step.

The same works for --. It subtracts 1 instead.

2. What Infosys actually asks

The official 2020 sample did not use ++ at all. It wrote j = j + 1 instead [CONFIRMED — official sample 2020]. So treat ++ as something that has appeared in recent reports, not in the sample.

Candidates from the 2025 exams reported three questions of this kind, all from one coaching video [REPORTED]:

  • Start with i = 5. Which of four statements leaves both result and i equal to 6?
  • Start with i = 2. Which expression, built from i++ and ++i, prints 7?
  • A loop that uses ++x and x-- and has to be traced to see that it never ends.

The pseudocode section is 5 questions worth 10 marks, so each question is worth 2 marks [LIKELY]. These are among the quickest questions in the section if you know the rule. You can answer one in under a minute.

3. The method

Use a small table. It stops almost every mistake.

  1. Write the start value of i.
  2. Go left to right. Take one piece of the expression at a time.
  3. For each piece, write three things: what i was, the value used, and what i is now.
  4. Combine the values used with the plus and minus signs, in order.
  5. Read off i last. Many questions ask for i as well as the result.

Here is the table for i = 5 and one piece each.

Piece i before Value used i after
i++ 5 5 6
++i 5 6 6
i-- 5 5 4
--i 5 4 4

Why left to right? Java promises it. The Java language specification says the operands of an operator are evaluated from left to right, and that the left one is fully evaluated before the right one starts. The Infosys pseudocode reads like Java, so use the same order.

4. Shortcuts and when they fail

Final i in one step. After the whole expression, i equals the start value plus the number of ++ minus the number of --. It does not matter where they sit. It fails when the expression also assigns to i, for example i = i++. Then trace it with the table.

Result from one column. The result is built only from the "value used" column, using the signs in the question. Build the column first, then add and subtract. It fails if you read the "i after" column by mistake. If the expression has multiplication, follow the usual order of operations on the values you wrote down.

Loop shortcut. If the loop tests i and each pass adds 1 to i, the number of passes is how far i has to travel. Trace two passes to see the pattern, then count. It fails if i also changes somewhere else in the loop body. Then trace every pass.

5. Worked examples

Every output below was checked by compiling and running real Java.

Example 1 (the basic rule). i = 5. What do result = i++ and result = ++i give?

With i++ the value used is 5 and i becomes 6. So result is 5 and i is 6. With ++i the value used is 6 and i is 6. So result is 6 and i is 6. Answers: 5 and 6, then 6 and 6.

Example 2 (a plain i after a post-increment). i = 3. result = i++ + i.

i++ uses 3, and i becomes 4. The plain i that follows reads 4. So result is 3 + 4 = 7, and i is 4.

Example 3 (pre then post). i = 2. result = ++i + i++.

++i makes i 3 and uses 3. Then i++ uses 3 and makes i 4. So result is 3 + 3 = 6, and i is 4.

Example 4 (three pieces and a minus). i = 6. result = i-- - --i + i.

Piece i before Value used i after
i-- 6 6 5
--i 5 4 4
i 4 4 4

Combine with the signs: 6 − 4 + 4 = 6. Final i is 4.

Example 5 (a loop that prints). i = 1. Loop while i < 4. Compare printing i++ with printing ++i.

With Print i++ the loop prints 1 2 3, and i ends at 4. Each pass prints the old value, then adds 1. With Print ++i the loop prints 2 3 4, and i ends at 4. Each pass adds 1, then prints. The loop stops in both cases when i reaches 4, but the printed lists differ.

6. Traps

  • Thinking i = i++ adds 1. It does not. In Java, i stays at 5 if it started at 5. The old value is handed back, then stored into i, which overwrites the increment. By contrast i = ++i gives 6.
  • Stopping at the result. If the question asks for i, write both columns.
  • Reading right to left. Some web pages say "undefined behaviour". That is a C idea. The Infosys questions read like Java, so go left to right.
  • Treating ++i + ++i as 2 × (i + 1). The second ++i sees the first one's change. If i = 2 it is 3 + 4, which is 7.
  • Assuming a loop ends. ++x followed later by x-- can bring x back to where it started. Trace two passes.

8. Recap in 60 seconds

  • ++i: add 1, then use it. i++: use it, then add 1. Either way i ends one higher.
  • Go left to right. Use the three-column table: i before, value used, i after.
  • Result = the "value used" column, combined with the signs. Final i = start ± the number of ++ and --.
  • i = i++ leaves i unchanged. i = ++i adds 1.
  • In a loop, trace two passes before you decide how it ends.
